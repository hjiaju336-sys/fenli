# 移动端独立前端方案

> 原则：桌面/移动两个独立HTML，共用一套后端API。不走应用商店，浏览器直接访问。

## 一、架构

```
server.py（不变）
  ├── /       → 自动检测设备 → 桌面→index.html / 手机→m.html
  └── /m.html → 移动端入口（也可手动访问）

static/
  index.html    ← 桌面端（保留，可精简）
  m.html        ← 移动端（新建，独立开发）
  manifest.json ← PWA快捷启动
  sw.js         ← 离线缓存
```

## 二、移动端页面结构

### 底部Tab导航（4个Tab，固定底部）

### 各Tab内容

| Tab | 桌面端对应 | 移动端设计 |

| 首页 | page-home | 快速开始按钮+最近游玩+公告 |

| 我的 | page-profile+page-suggestions+page-admin | 个人中心+建议+管理入口 |

### 聊天界面（核心体验）


## 三、移动端 vs 桌面端

| 功能 | 桌面 | 移动 |
|------|------|------|
| 聊天区 | 三栏布局，侧栏+聊天+变量 | **全屏聊天，变量底部抽屉** |
| 模板管理 | 网格卡片 | **列表+搜索** |
| 编辑器 | 8步向导（大屏） | **简化版：填名→填JSON→上传（高阶用户用）** |

| 管理面板 | 7Tab左右分栏 | **手风琴折叠菜单** |
| 世界书 | 变量面板常驻 | **+按钮弹出编辑** |
| N值选择 | 下拉框 | **滚轮选择器** |
| 玩家头像 | API弹窗内 | **我的Tab内** |

## 六、发布方式

1. 把`m.html`部署到服务器
2. 用户手机浏览器访问网址
3. 浏览器自动弹"添加到主屏幕"
4. 桌面出现App图标→点击全屏打开
5. 微信/QQ内打开→提示"在浏览器中打开"→同样流程

## 七、设备检测

```python
# server.py 根路由改为：
@app.get("/")
async def root(request: Request):
    ua = request.headers.get("user-agent", "").lower()
    is_mobile = any(t in ua for t in ["mobile", "android", "iphone", "ipad"])
    if is_mobile:
        return HTMLResponse(_MOBILE_HTML, headers=...)
    return HTMLResponse(_DESKTOP_HTML, headers=...)
```
