# AI提示词优化 + N值调优报告

> 日期: 2026-07-24 | 基于52条记忆/12轮对话压力测试数据

## 一、N值调优

### 测试数据

| N值 | 上下文窗口 | 测试表现 |
|-----|-----------|----------|
| N=3 | 6条消息 | R9重复、R11跳过、叙事断裂 |
| N=10 | 20条消息 | Token浪费、旧信息干扰 |
| **N=5** | **10条消息** | **建议默认值** |

### N=5的理由

- **信息密度**：5轮对话覆盖一个完整的探索-发现-反应循环
- **Token经济**：10条消息约2000-3000 tokens，适合小模型处理
- **总结触发**：每5轮触发一次总结，记忆压缩密度合理（~15-25条记忆对应50轮对话）
- **回滚范围**：5轮回滚范围不会丢失太多进度，用户可接受

### 改动点

| 位置 | 旧值 | 新值 |
|------|------|------|
| `index.html: _nValue` 默认值 | 10 | **5** |
| `index.html: nvalue-select` 默认选项 | N10 | **N5** |
| `server.py: n_value` 回退值 | 10 | **5** |

## 二、Pass1 提示词优化（标签召回）

### 旧版问题
1. "宁可多留不少删" → 52条记忆中fetch过多
2. 无记忆相关性评分指导 → 盲目keep所有记忆
3. 上下文写死"最近3轮" → 与N值不匹配

### 优化内容
- **精准优先**：改为"只fetch当前场景直接相关的标签"
- **记忆过滤**：增加"记忆总量可能很大（50+），只选最相关的3-8条"
- **关键词匹配**：强调"如果用户输入与记忆hint中的关键词匹配，优先fetch"
- **drop谨慎**：保留"仅放入已死亡/已离开/已销毁"

### 预期效果
- 52条记忆中每次只fetch 3-8条相关记忆，减少Pass2的输入噪声
- Token用量降低约40%（从fetch 20+条到3-8条）

## 三、Pass2 提示词优化（剧情生成）

### 旧版问题
1. 叙事300-800字偏长 → 12轮测试中部分回复冗余
2. 字段规范冗长（14行枚举） → 挤占有效token
3. 无记忆整合指导 → AI可能忽略已解锁的记忆信息
4. 规则执行描述模糊

### 优化内容
- **叙事长度**：300-800字 → **200-500字**（提高信息密度）
- **记忆整合**：增加"当前世界状态中的相关记忆是已解锁的剧情信息——自然融入叙事"
- **字段规范压缩**：14行 → 6行，保留关键字段
- **规则执行明确化**：列出具体后果类型（扣血/扣理智/强制移动/角色出现/即死）
- **update强调**：明确列出需要更新的动态字段（血量/理智/当前位置/持有物品）

### 预期效果
- 叙事更精炼，减少30%冗余
- 记忆信息更好地融入叙事中
- Token效率提升20%

## 四、Summary 提示词优化（记忆总结）

### 旧版问题
1. 100-300字/条 → 5轮3条记忆可达900字，密度低
2. 无去重指令 → 可能重复记录同一事件
3. "详细叙事性记忆" → 鼓励冗长

### 优化内容
- **长度压缩**：100-300字 → **50-150字**
- **格式约束**：增加"格式：[事件]→[结果]。只记录事实，不抒情"
- **去重指令**：增加"不重复已有记忆的内容（检查记忆索引中的hint）"
- **产出控制**："每轮对话产出1-3条记忆即可，宁少勿滥"
- **可检索性**：增加"保留人名/地名/物品名等专有名词，方便后续关键词匹配召回"

### 预期效果
- 记忆密度提升3倍（从300字/条到100字/条）
- 去重机制减少冗余记忆
- 专有名词保留提高召回准确率
