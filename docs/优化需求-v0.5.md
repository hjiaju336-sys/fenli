# 优化需求文档 — AI 无限流规则怪谈游戏

> 版本: v0.5.2 | 日期: 2026-07-24 | 状态: 12条需求完成 + 测试驱动新增需求

---

## 总览

12 条优化需求，按影响层级分为：**数据库层（5张新表+3表改造）→ API 层（~20个新端点）→ 前端层（主题系统/自适应/交互特效）→ 基础设施（图片上传/审核接口/管理面板）**。

预估总工时约 **21 人天**，建议分 4 个阶段推进。

## 一、数据库改造

### 1.1 新建表（5张）

```sql
-- 积分账户
CREATE TABLE point_accounts (
    player_id VARCHAR(255) PRIMARY KEY,
    balance INT DEFAULT 0,
    total_earned INT DEFAULT 0,
    total_spent INT DEFAULT 0,
    sign_in_streak INT DEFAULT 0,       -- 连续签到天数
    last_sign_in_date VARCHAR(20),
    created_at VARCHAR(50)
);

-- 积分流水（审计用）
CREATE TABLE point_transactions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    player_id VARCHAR(255),
    amount INT,                          -- 正=收入, 负=支出
    reason VARCHAR(100),                 -- sign_in / rate_template / comment / upload_template / play_reward / chat_cost / exchange / admin_grant
    ref_id VARCHAR(255),                 -- 关联对象ID（模板ID/兑换码等）
    created_at VARCHAR(50)
);

-- 兑换码
CREATE TABLE exchange_codes (
    code VARCHAR(64) PRIMARY KEY,        -- HMAC签名生成，全局唯一
    points INT,                          -- 面值
    batch_id VARCHAR(64),                -- 批次号（管理员生成时标记）
    created_by VARCHAR(255),             -- 管理员ID
    used_by VARCHAR(255) DEFAULT NULL,   -- 兑换者ID
    used_at VARCHAR(50) DEFAULT NULL,
    is_used TINYINT DEFAULT 0,
    created_at VARCHAR(50)
);

-- 模板评分+评论
CREATE TABLE template_ratings (
    id INT AUTO_INCREMENT PRIMARY KEY,
    target_type VARCHAR(32),             -- 'preset'(标准) / 'cloud'(云端共享) / 'user'(自建)
    target_id VARCHAR(255),              -- filename(标准) / shared_copies.id / save_slots.id
    player_id VARCHAR(255),
    rating TINYINT,                      -- 1-5 星
    created_at VARCHAR(50),
    UNIQUE KEY uk_rate (target_type, target_id, player_id)
);

CREATE TABLE template_comments (
    id INT AUTO_INCREMENT PRIMARY KEY,
    target_type VARCHAR(32),
    target_id VARCHAR(255),
    player_id VARCHAR(255),
    username VARCHAR(255),
    content TEXT,
    parent_id INT DEFAULT NULL,          -- 回复某条评论（NULL=一级评论）
    likes INT DEFAULT 0,
    is_approved TINYINT DEFAULT 1,       -- 审核标记（接口预留，默认通过）
    created_at VARCHAR(50)
);

-- 评论点赞
CREATE TABLE comment_likes (
    comment_id INT,
    player_id VARCHAR(255),
    PRIMARY KEY (comment_id, player_id)
);

-- 评论举报
CREATE TABLE comment_reports (
    id INT AUTO_INCREMENT PRIMARY KEY,
    comment_id INT,
    reporter_id VARCHAR(255),
    reason VARCHAR(500),
    is_resolved TINYINT DEFAULT 0,
    resolved_by VARCHAR(255),
    created_at VARCHAR(50)
);

-- 玩家建议
CREATE TABLE suggestions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    player_id VARCHAR(255),
    username VARCHAR(255),
    category VARCHAR(50),                -- bug/feature/other
    content TEXT,
    status VARCHAR(20) DEFAULT 'pending', -- pending / acknowledged / implemented / declined
    admin_reply TEXT,
    created_at VARCHAR(50)
);
```

## 二、API 层新增/改造清单

### 2.1 图片上传

支持格式: PNG/JPG/GIF/WebP，文件名用 UUID 防冲突。

### 2.2 双 API 配置（前端改造为主，后端 WS 改造）

后端 `server.py` WebSocket handler 已有 `model_small` / `model_large` 参数接收，但当前前端传的是同一个 model。改造：

```python
# WS 接收改为:
{"type":"user_turn", "userInput":"...", "apiKey1":"...", "apiKey2":"...", "modelSmall":"...", "modelLarge":"..."}

# orchestrator 调用改为:
process_turn(api_key_small=ak1, api_key_large=ak2, model_small=model1, model_large=model2, ...)
```

前端两个独立 API Key 输入框，各自带 URL/密钥/模型拉取/手动输入。

## 三、前端改造详细设计

### 3.1 自定义底图与头像（需求1）

**头像系统：**
- 聊天界面改为气泡式布局，玩家消息前显示玩家头像（圆形，40px），AI 消息前显示 AI 头像
- 玩家头像：在设置面板中上传，存 localStorage base64。右键头像可更换
- AI 头像：每个副本可设定不同的 AI 头像（NPC/世界观代表形象），在模板数据中作为 `ai_avatar` 字段
- 角色数据结构增加 `头像` 字段（tag_detail 中），侧边栏角色卡片显示角色头像

**底图替换：**
- 登录页/首页/模板页/游戏页各可设置独立底图
- 设置入口：各页面右上角小画笔图标，点击弹出底图选择器（本地上传 / 预设图库 / 恢复默认）
- 存 localStorage，key 格式：`mvp_bg_{pageName}`

**云端共享图片：**
- 模板编辑器中可上传封面图和角色图片
- 上传到服务器 `/static/uploads/`，模板 JSON 中存 URL 引用而非 base64 数据
- 加载云端模板时同时拉取关联图片

### 3.2 多主题+鼠标特效（需求2）

**三套主题 CSS 变量覆盖：**

| 变量 | default（羊皮卷） | night（夜间护眼） | pink（粉色可爱） | horror（血腥诡异） |
|------|-------------------|-------------------|------------------|---------------------|
| `--bg` | `#3a2010` | `#1a1a2e` | `#3a1828` | `#0a0000` |
| `--surface` | `#faf0dc` | `#2a2a3e` | `#fff0f5` | `#1a0a0a` |
| `--parchment` | `#f5e6c8` | `#2e2e44` | `#ffe4ec` | `#2a1010` |
| `--blood` | `#8b2020` | `#4a6fa5` | `#d4648a` | `#cc0000` |
| `--gold` | `#c9a050` | `#6a8abf` | `#e8a0b4` | `#8b0000` |
| `--ink` | `#1a1008` | `#c8c8dc` | `#4a2030` | `#ccc` |
| `--font` | 衬线 | 无衬线 | 圆体 | 衬线 |

**鼠标特效：**
- Canvas 实现的彩色粒子拖尾（各主题配色不同：night=蓝紫, pink=粉金, horror=暗红）
- 可选开启/关闭（设置面板中开关，存 localStorage）
- 性能保护：移动设备自动禁用

**交互反馈：**
- 所有按钮/卡片 hover 时 `transform: translateY(-2px)` + `box-shadow` 增强
- 过渡动画 `transition: all 0.2s ease`
- 点击时 `transform: scale(0.97)` 按压反馈

**对话消息美化：**
- 用户消息：右对齐，浅色气泡背景，圆角 12px 左上右下
- AI 消息：左对齐，羊皮纸纹理气泡，圆角 12px 右上左下
- **引号高亮**：AI 消息中 `"..."` 或 `「...」` 包裹的文字自动渲染为特殊颜色（加粗+主题色），方便识别 NPC 对话
- 实现：正则 `/"[^"]+"/g` 和 `/「[^」]+」/g` 匹配后用 `<span class="quote-highlight">` 包裹

### 3.3 布局重构+自适应（需求3）

**游戏界面新布局：**
```
┌────────────────────────────────────────────┐
│ 顶栏：世界名 | 规则按钮 | 状态指示器      │
├────────┬───────────────────┬──────────────┤
│ 侧栏   │                   │ 变量面板     │
│ 角色   │   聊天区域        │ (可折叠)    │

│ 操作   │                   │             │
├────────┴───────────────────┴──────────────┤
│ 底栏：输入框 + 发送 + 存档 + 回滚 + 设置  │
└────────────────────────────────────────────┘
```

- 侧栏宽度：desktop 200px, tablet 160px, mobile 隐藏（汉堡菜单）
- 变量面板：desktop 220px, tablet 可折叠, mobile 底部抽屉
- 聊天区最小宽度 400px，flex 自动撑满
- 断点：mobile < 768px, tablet 768-1024px, desktop > 1024px
- 输入框始终在底部，移动端固定定位

**自适应要点：**
- `rem` 单位为主，`px` 仅用于边框/阴影
- `max-width: 1400px` 大屏居中，小屏 100vw
- 字体 `clamp(12px, 1.5vw, 16px)` 自适应
- 移动端卡片改为横向滚动而非堆叠

### 3.4 开场白+变量侧栏优化（需求4）

**开场白：**
- 模板 JSON 新增 `opening_monologue` 字段（字符串，由模板作者填写）
- 玩家自建模板编辑器中增加"开场白"输入框（textarea, 2行高）
- 进入游戏时，开场白以 **AI 消息格式** 作为第一条消息展示（与后续 AI 叙事格式一致）
- 示例："欢迎来到血月医院。今晚是你在急诊室值夜班的第三天，窗外的月亮不知何时变成了暗红色。走廊尽头的灯忽明忽暗，你听见远处传来微弱的呼救声..."

**变量侧栏重构：**
- 当前问题：侧栏仅展示玩家角色属性，其他变量不可见
- 改造后展示 **所有 active 标签** 的摘要信息：
  - World: 表面介绍（前30字）
  - Map: 当前地图描述（前30字）
  - Rule: 表面规则列表（只显示规则名，点击展开）
  - Character: 所有角色名称+血量/状态
  - Item: 持有物品名称列表
- **剧透机制**：`tag_detail` 中以 `隐藏` 开头或 `_` 前缀的字段默认为剧透变量
  - 变量面板底部有"🔍 剧透模式"开关
  - 点击后弹出确认弹窗（"剧透可能影响游戏体验，确定开启吗？"）
  - 确认后展示所有隐藏变量，标记为红色边框以示区分
  - 剧透模式下也可编辑隐藏变量（供调试用）

**spoiler 字段判定规则（前端实现）：**
```javascript
function isSpoilerField(key) {
  return key.startsWith('隐藏') || key.startsWith('_') || 
         ['真实规则','隐藏真相','隐藏区域','隐藏效果','真实身份'].includes(key);
}
```

| 管理员赠送 | 任意 | — | 管理面板操作 |

**测试阶段**：新注册用户默认赠送 99999 积分（可通过管理面板调整注册赠送额度）。

**兑换码机制：**
- 管理面板生成：选择面值+数量+批次名 → 批量生成唯一码
- 码格式：`FL-XXXX-XXXX-XXXX`（16位字母数字，HMAC-SHA256签名防伪造）
- 生成算法：`code = "FL-" + base32(hmac(secret, f"{batch_id}:{seq}:{points}:{random}"))[:12]`，格式化为4位一组
- 服务端验证：解码 → 验签 → 检查是否已使用 → 充值 → 标记已使用
- 管理面板可查看兑换码使用情况（批次/生成者/使用者/使用时间）

**付费埋点：**
- `point_transactions` 表 `reason='exchange'` 记录所有兑换
- 预留 `payment_orders` 表结构（订单号/金额/积分/状态/创建时间），暂不实现
- 前端首页底部预留"获取积分"入口（当前显示"敬请期待"）

## 六、风险与注意事项

1. **图片存储**：localStorage 有 5-10MB 限制，需在前端做容量检测，超出时提示清理或切换服务器存储
2. **积分经济平衡**：当前数值设计为初版，上线后需根据实际数据调整（管理面板可调参数）
3. **评论审核**：阶段三暂时默认通过，后续接入 AI 审核仅需改 `POST /api/review/comment` 内部逻辑
4. **移动端适配**：鼠标拖尾/悬浮特效在移动端应自动禁用
5. **兑换码安全**：HMAC 签名密钥存在服务器环境变量，不可泄漏；兑换码生成日志需完整保留
6. **管理面板安全**：所有 `/api/admin/*` 端点需校验 `is_admin=1`，中间件层统一拦截

## 七、测试驱动新增需求 (v0.5.2)

以下需求在多轮系统测试中发现并实现：

### 需求13: 消息编辑

玩家可逐条修改已发送消息，AI基于新内容重新生成回复。
- 每条用户消息hover显示✎按钮
- 点击→textarea编辑→确认修改→通过WebSocket重新发送
- AI基于修改后的消息生成新回复（区别于原始回复）
- 取消→恢复原消息

### 需求14: 逐条回滚

玩家可回滚到任意历史消息的存档状态。
- 每条用户消息hover显示↩按钮
- 点击→确认弹窗→POST /api/rollback/{turn}
- 服务端查找该turn之前的最近存档→清空当前标签/记忆→恢复存档
- `data-turn`属性跟踪每条消息的轮次编号

### 需求15: 聊天历史存档

存档时保存完整聊天记录，加载时恢复。
- doSave()序列化DOM消息为`recent_messages`数组存入save_data
- 加载存档时通过`window._savedMessages`传递→init_state渲染
- 恢复的消息自动附加✎/↩按钮
- 支持system/AI/user三种消息类型的完整恢复

### 需求16: 可配置N值系统

玩家可调整上下文窗口大小，影响AI记忆范围。
- 游戏输入栏左侧N值选择器（N3/N5/N7/N10/N15/N20）
- 控制：AI上下文窗口（N×2条消息）/ 总结触发频率 / 回滚轮次范围
- localStorage持久化 + WS每轮透传nValue
- 默认值N=5（经压力测试验证最优）

### 需求17: 双Pass提示词优化

基于52条记忆+12轮对话的压力测试数据，优化两轮AI调用。
- Pass1: 精准召回取代"宁多勿少"，记忆limit 3-8条，关键词匹配引导
- Pass2: 叙事200-500字（原300-800），字段规范压缩50%，记忆自然融入
- Summary: 50-150字/条（原100-300），[事件]→[结果]格式，去重指令
- Token总消耗降低~33%

### 需求18: orchestrator防崩溃加固

所有str.join()调用点防御None值。
- hard_sync.py: 全局_sj()安全join函数
- pass1.py: 4处join改为`str(x) for x in ... if x is not None`
- pass2.py: 1处join同款加固
