## 方向一：叙事者系统 🎭

### 概念

类似《环世界》的叙事者选择系统。玩家在开局或设置中切换"叙事者"——每个叙事者是一位有独立人格的存在，改变 AI 的叙事风格和游戏难度。

### 双面结构

叙事者有两个完全解耦的面：

| | 玩家面（展示层）| AI 面（规则层）|
|------|------|------|
| **用途** | 选择界面的 flavor text | 喂给 Pass2 的 prompt patch |
| **内容** | 名字、性格独白、风格标签、难度星级 | 语调约束、词汇规范、难度参数、事件概率 |
| **是否进入 AI** | ❌ 纯展示 | ✅ 拼入系统提示词 |
| **可独立修改** | 换人设文案不改规则 | 调难度不改人设 |

### 示例

```
玩家在 UI 看到：                   Pass2 接收到：

「镜中人」🪞                      SYSTEM: 你是"镜中人"，一面古老镜子中的存在。
"我是镜子里的倒影，                使用优雅低沉的语调，多用隐喻和暗示。
 你每一次选择，我都在看着。"        减少直接暴力描写，增加心理恐怖元素。
                                 选项设计偏向道德困境而非物理危险。
风格：文艺恐怖 | ★★★              危险事件概率 0.6，即死阈值 0.15。
```

### 本期（v0.8.x）接口预留

- **pass2.py: `run_pass2()`** 预留 `storyteller_config: dict = None` 参数，当前传 `None` 时用默认 prompt，未来传 storyteller 配置时覆盖对应段落
- **PASS2_SYSTEM_PROMPT** 拆分为多个段落变量（人设段 / 风格段 / 难度段 / 基础规范段），当前合并为一个字符串，未来按 storyteller 配置分别组装
- **DB** 预留 `storytellers` 表结构设计（name / persona_display / prompt_patch / difficulty_params），暂不建表
- **前端** 游戏设置页预留叙事者选择区域（可先隐藏），数据结构约定 `{storyteller_id, display_name, style_tags[], difficulty_stars}`

## 方向二：架构模块化 / 题材插件化 🔌

### 概念

将"规则怪谈"题材从引擎中抽离，使系统成为一个**可换皮的 AI 叙事引擎**。换题材只需加载不同的题材插件包，引擎层零改动。

### 引擎层 vs 题材层

```
引擎层（不变量，所有题材共用）        题材层（插件，每个题材一套）
─────────────────────────       ─────────────────────────
• 双 Pass AI 编排                  • 标签分类定义（category 枚举）
• 标签召回 + 硬同步                  • 每个分类的字段 schema
• 叙事生成（基础框架）               • Pass2 系统提示词
• Hook 触发引擎                     • Hook 效果函数
• WebSocket 推送                   • 前端主题/美术资源
• 积分/用户系统                     • 预设模板（preset/copy）
```

### 目标题材（示例）

| 题材 | 标签分类 | 核心系统 |
|------|------|------|
| 规则怪谈（当前）| world / map / rule / character / item | 血量 / 理智 / 即死 |
| 科幻生存 | planet / ship / faction / resource / anomaly | 氧气 / 燃料 / 辐射 |
| 恋爱模拟 | scene / love_interest / event / item | 好感度 / 关系网 / 心情 |
| 侦探推理 | location / suspect / clue / testimony | 证据链 / 推理进度 / 嫌疑人状态 |

### 本期接口预留

- **标签系统**：当前 `category` 是硬编码的 `(world/map/rule/character/item)`，下一步应在 `src/schema.py`（新建）中定义 `CategorySchema`，让题材插件注册自己的分类和字段规范
- **data_ops 校验**：Pass2 输出的 `tag_detail` 字段校验逻辑应参数化，根据当前题材 schema 动态验证，而不是硬编码字段列表
- **系统提示词**：`PASS2_SYSTEM_PROMPT` 中的"字段规范"段应从题材配置中生成，而不是手写固定文本
- **Hook 效果**：`common.js` 中的 `_EFFECT_DISPATCH` 已有 48 个效果函数，架构良好。题材专属效果可通过 `_EFFECT_DISPATCH` 的扩展机制注册

## 方向三：多人共享世界 🌐

> 2026-08-01 深度讨论后更新

### 概念

真正的共享世界——不是"只有残留痕迹"，而是 A、B、NPC 同时存在于同一个世界中，互相知情。标签数据库是共享通道，时间异步，玩家通过世界状态间接互动。

### 已敲定的决策

| 决策 | 结论 |
|------|------|
| **模型** | B+C 融合：共享标签通道 + 异步玩家 + 世界状态互通 |
| **世界时间** | 独立于玩家，统一流逝，不等任何人。不是"玩家的第N天"，而是"世界的第N天" |
| **时间粒度** | 世界按现实时间推进（TBD：现实1天 = 游戏几天的比例） |
| **同步点** | 空间（地图节点/房间）。同房间 = 可感知对方存在、互动 |
| **共享范围** | 环境共享（map/item），角色状态独立实例还是共享待定（涉及 A 惹怒的 NPC 是否也针对 B） |
| **追忆系统** | ❌ 不需要。玩家回来自己问 NPC + 标签召回自然覆盖 |
| **付费设计** | ❌ 不卖时间道具（破坏体验）。FOMO 本身是动机——不玩就错过 |
| **适用性** | 仅限多人模式。单人模式世界等玩家，不自主演化 |

### 核心架构

```
世界时间线（共享，不等任何人）
─────────────────────────────────────────────────────►
      │                    │                    │
    Day 1               Day 2               Day 3
      │                    │                    │
    A在线，3步         A离线               A上线，回病房
    B在线，1步         B在线，5步          B在线
      │                    │                    │
                                                   │
                                    同房间 → 碰撞检测
                                    ├─ Pass2 提示"房间里有另一个人"
                                    ├─ 可选择互动（对话/交易/一起行动）
                                    └─ 各自行动也可，叙事互相提及
```

### 共享 vs 独立

```
同一玩家进入前（A时间）        世界标签（全局）         同一玩家进入后（B时间）
                                                   
A 推门                          月光病房：              B 推门
  │                              - 镜子碎了 ←──update──┘ 看到碎镜子
  ├─ 惹怒护士长                                          
  │   └→ update：护士长.态度=愤怒                         
  │                                                       
  └→ B 进入同一房间                                       
      Pass2 注入：房间里有另一个玩家（A）                   
      B 的叙事提到 A 的存在                                
      B 可以和 A 对话/交易                                 
```

### 世界自主演化（世界心跳）

每 N 小时（TBD，如 6h），系统触发一次"世界心跳"：

```
输入：
  • 当前活跃标签摘要
  • 最近玩家行动记录（避免矛盾）
  • 上次心跳以来的时间

AI 生成：
  • 3-5 个剧情事件（不是完整叙事，是"发生了什么"）
  • 对应 data_ops，写入共享标签

效果：
  • 玩家离线 2 天回来 → NPC 搬了、规则触发了、新尸体出现了
  • Pass1 召回自然呈现变化
  • 不需要追忆面板

成本：
  • 4 次/天 × 30 天 = 120 次 AI 调用/月
  • 几块钱
```

### 要解决的问题

| 问题 | 初步思路 |
|------|------|
| **信息过载** | 100 人在同一地图写标签 → 时间衰减权重，过期标签降低召回优先级 |
| **多人同场并发** | 同房间多人同时行动 | 按现实到达顺序，先到先手；世界心跳串行化写入 |
| **写冲突** | 多人同时改同一标签 | 乐观锁（version 字段），冲突取最后写入 |
| **叙事污染** | 恶意玩家写垃圾标签 | 标签分"全局可见/仅自己可见/管理员可见" |
| **NPC 状态** | A 惹怒了 NPC，B 是否受影响 | 待定——可能角色部分共享，部分实例化 |

### 本期（v0.8.x）接口预留

- **标签表**：预留 `visibility` 字段（global / private / admin_only），默认 `global`
- **Pass1 召回**：预留 `player_location` 参数，当前不传时不过滤，未来按空间过滤
- **data_ops 写入**：预留 `player_id` 字段（标记谁写入的），当前用 NULL
- **世界心跳**：预留 `world_tick()` 函数框架（asyncio task），当前不调用
- **前端**：多人模式下消息区分样式（自己 / 其他玩家 / 世界事件）的概念预留
